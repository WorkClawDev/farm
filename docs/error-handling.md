# 异常处理规范

本项目统一使用三类输出：

## `push_error()`

用于游戏无法继续、数据损坏、关键资源缺失、脚本契约被破坏的情况。

典型场景：

- JSON / 资源文件解析失败
- 必须存在的场景、脚本、节点加载失败
- 当前操作不可能恢复，继续执行只会产生错误状态

## `push_warning()`

用于可恢复异常或降级路径。

典型场景：

- 可选资源缺失，但系统可以降级继续
- 输入非法，但调用方可以重试
- 某个功能分支跳过执行，但主流程仍可继续

## `print()`

仅用于调试日志和状态追踪，不应用于错误分级。

典型场景：

- 初始化完成
- 状态变化
- 运行时诊断信息

## 实践约束

- 不要用 `print()` 代替 `push_warning()` 或 `push_error()`
- 资源/配置解析失败优先考虑 `push_error()`
- 用户输入不满足条件、但系统仍可继续时使用 `push_warning()`
- 新代码优先给错误信息加上模块前缀，例如 `[ShopSystem] ...`
